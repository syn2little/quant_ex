# Phase8 portfolio risk-cap diagnostic inputs - 2026-05-19

## Scope and guardrails

This note defines the minimum daily and fold-level artifacts needed before any portfolio risk-cap prototype. It is diagnostic-only and keeps `gate_m008` fixed as the reference candidate.

No market data refresh, rebalance, live notification, config promotion, full WFV, or signal-threshold micro-tuning is in scope. External scout findings are hypothesis input only; local artifacts and tests remain binding.

## Why this artifact is needed

Recent Phase8 attribution points to transient and fold-specific weakness rather than a validated signal-threshold repair. A risk cap should therefore be evaluated as a portfolio construction/risk overlay with explicit pre/post counterfactuals, not as another tuned signal gate.

The minimum input contract should make the future prototype answer three questions:

1. Did the cap reduce realized drawdown or volatility during known weak periods?
2. Did it preserve enough exposure during normal periods to avoid alpha starvation?
3. Did it introduce hidden costs through turnover, concentration, or delayed re-entry?

## Minimum daily artifacts

Each trading day in a diagnostic run should export one row per strategy/account state, plus optional per-position rows for holdings and trade detail.

## Cap state contract

A future pure function should compute cap state using only lagged inputs available before the next trade date.

Suggested v0 state machine:

| State | Entry condition | Exit condition | Allowed action |
| --- | --- | --- | --- |
| `inactive` | Vol and drawdown within budget | `rolling_vol` or drawdown breaches watch threshold | Keep `cap_multiplier = 1.0`. |
| `watch` | Near budget breach | Risk normalizes or cut threshold breaches | No forced cut yet; log only. |
| `cut` | Drawdown or vol exceeds cap threshold | Recovery conditions hold for a minimum cool-down | Reduce gross exposure by deterministic multiplier. |
| `recover` | Risk normalized after cut | Full cool-down complete | Step exposure back toward baseline. |
| `blocked` | Missing/invalid risk inputs | Inputs become valid | Keep baseline or fail closed by explicit config, never silently. |

State transitions must not depend on future returns, realized post-cap outcomes, or manually inspected weak periods.

## Pre/post cap counterfactual rules

1. Baseline artifacts are the immutable `pre_cap_*` reference.
2. `post_cap_*` fields are generated by a deterministic overlay that consumes only baseline daily state, holdings, trades, and lagged risk metrics.
3. The first prototype should scale exposure, not alter ranking, top-k, n-drop, hold threshold, or model signal.
4. Turnover and cost deltas must be materialized before comparing returns.
5. Any apparent improvement from avoiding a known weak fold remains `diagnostic_only` until validated outside the design window.
